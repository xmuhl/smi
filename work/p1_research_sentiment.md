# P1 研究：市场情绪模块历史回补数据源实测

- 日期：2026-08-15（实测于环境"今天"= 2026-08-14 之后）
- 环境：Windows + smi\.venv，akshare 1.18.88
- 范围：回补 2026-07-20~08-13 以及更早交易日的市场情绪字段
- 性质：**只读研究**，未修改任何代码/数据文件；临时脚本放 smi\tmp 下（p1_*.py），不提交。
- 关键结论速览：**乐咕乐股 `stock_market_activity_legu()` 在 akshare 1.18.88 里是"仅当日"快照，无法回补历史**；东财涨停池各表统一以 2026-07-27 为历史窗口下界。因此 07-20~08-13 的涨跌家数**全部不可直接回补**，只有 07-27 起的涨跌停/炸板/连板/封板可用。

---

## 1. 候选源实测结果

### 1.1 ak.stock_market_activity_legu() —— 乐咕乐股市场活跃度（最关键的候选，实测**不可用**）

- **签名**：`() -> DataFrame`，**不接受日期参数**。
- **返回**：仅一张 12x2 的当日快照表，列 = `['item','value']`。实测（今天=2026-08-14）返回：

    item       value
    上涨       2322.0
    涨停         63.0
    真实涨停      56.0
    ...         ...
    停牌          3.0
    活跃度       44.59%
    统计日期   2026-08-14 15:00:00

- **实现本质**：akshare 该函数是*静读（live scrape）* legulegu.com/stockdata/market-activity 页面，page 上只有当前交易日的赚钱效应快照（实测 page 内出现且仅出现日期 `2026-08-14`，无日期导航、无 API 端点、无历史链接）。
- **历史范围**：**无**。无法回补 07-20~08-13 或任何历史交易日。
- **结论**：**不可用**。文档所谓"历史"仅指表格内各分项（上涨/涨停/真实涨停/跌停等）是当天历史累计，不是多交易日序列。

> 连带说明：任务背景称 legu 提供"沪深京A股上涨/下跌/平盘/涨停/跌停/炸板家数历史"。实测 1.18.88 只开放当日口径，无历史参数，也无其它 legu 历史市场活跃度接口（akshare 全函数扫描中与 market/activity/count/breadth/sentiment 相关的仅有 `stock_market_activity_legu()` 与 `stock_market_fund_flow()`）。

### 1.2 东财涨停池各历史表

| 函数 | 签名 | 07-20 | 07-24 | 07-27 | 08-04 | 08-13 |
|---|---|---|---|---|---|---|
| stock_zt_pool_em（涨停池） | (date) | EMPTY | EMPTY | rows=111 | 138 | 59 |
| stock_zt_pool_previous_em（昨日涨停） | (date) | EMPTY | EMPTY | rows=40 | 75 | 93 |
| stock_zt_pool_strong_em（强势股池） | (date) | EMPTY | EMPTY | rows=61 | 82 | 169 |
| stock_zt_pool_dtgc_em（跌停股池） | (date) | EMPTY | EMPTY | rows=6 | EMPTY(1) | 4 |
| stock_zt_pool_zbgc_em（炸板股池） | (date) | EMPTY | EMPTY | rows=13 | 15 | 36 |

- **窗口边界一致**：五张表统一在 **2026-07-27 起**有数据，07-24 及更早全部 EMPTY。这与现状标注"07-27 边界"完全一致并进一步确认（并非单表差异，而是东财服务端统一保留窗口）。
- (1) 注意：`dtgc`（跌停股池）在**窗口内**也可能返回 EMPTY —— 那是当日真实零跌停（08-04 无跌停股），并非窗口问题。**判定需先看日期**：< 07-27 → 不可得；>= 07-27 且 EMPTY → 真零。
- **可用列（涨停池 stock_zt_pool_em）**：`名称 / 涨跌幅 / 封板资金 / 首次封板时间 / 最后封板时间 / 炸板次数 / 涨停统计(如"4/4") / 连板数 / 所属行业`。其中 **`连板数`** 可直接求最高连板高度（见 3 节）；**`炸板次数`** 为单票开板次数，与炸板家数（zbgc 池行数）口径不同。
- **跌停池 stock_zt_pool_dtgc_em**：含 `连续跌停 / 开板次数 / 封单资金`；**炸板池 stock_zt_pool_zbgc_em**：行数即炸板家数，含 `炸板次数`。
- **ST 拆分**：各池都有 `名称` 列，可用现有 `is_st()`（名称前缀 *ST/S*ST/SST/ST）拆分。实测 08-13/08-04/07-27 当日 ST 涨停/跌停均为 0（当日无 ST 封板），但拆分机制可用。

### 1.3 ak.stock_zh_a_spot_em 当日快照是否支持历史

- **签名**：`() -> DataFrame`，**无日期参数**。
- **实测**：仅当日实时行情，不支持历史。与预期一致，**不可用于回补**。

### 1.4 其它（简要确认）

- 无 akshare 历史"涨跌家数"专用接口；涨跌家数覆盖全市场 5000+ 只，东财涨停/炸板池只覆盖封板样本，**无法由池反推涨跌家数**。
- 同花顺/新浪涨跌家数历史未纳入本报告（任务范围里 legu + 东财池优先，时间有限）。

## 2. 结论：07-20~08-13 各字段可回补矩阵

目标字段横向列出，行是区间/来源。✓=可回补，✗=缺口，△=可计算（基于池内数据）。

| 字段 | 07-20~07-24 | 07-27~08-13 | 来源 |
|---|---|---|---|
| 上涨家数 riseCount | **✗ 缺口** | **✗ 缺口** | 无（legu 仅当日 / spot 仅当日） |
| 下跌家数 fallCount | **✗ 缺口** | **✗ 缺口** | 同上 |
| 平盘家数 flatCount | **✗ 缺口** | **✗ 缺口** | 同上 |
| 停牌家数 suspendedCount | **✗ 缺口** | **✗ 缺口** | 同上 |
| 非ST涨停家数 | **✗** | ✓ 东财 zt 池 | 名称前缀拆分 |
| ST涨停家数 | **✗** | ✓ 东财 zt 池 | 名称前缀拆分 |
| 非ST跌停家数 | **✗** | ✓ 东财 dtgc 池（EMPTY=真零，需按日期判定） | 名称前缀拆分 |
| ST跌停家数 | **✗** | ✓ 东财 dtgc 池 | 名称前缀拆分 |
| 炸板家数 brokenLimitCount | **✗** | ✓ 东财 zbgc 池行数 | |
| 涨停封板率 | **✗** | △ = 涨停池家数/(涨停池+炸板池) | 08-13≈62.11% |
| 最高连板高度 | **✗** | △ = 涨停池 `连板数`.max() | 08-13=5, 08-04=7 |
| 连板>1 家数（梯队） | **✗** | △ = 涨停池 `(连板数>1)`.sum() | 08-13=22 |

**一图总结**：07-27 之前的任何字段都无法回补；07-27 起除"涨跌家数"缺失外，其余全部可由东财池补全。

## 4. 对 07-24 及更早（东财池窗口外）的诚实处理建议

- **明确缺口，不用 0 伪装或缺省填充**：07-20~07-24 的涨停/跌停/炸板/封板率/连板高度全部不可得。逐字段置 None，并在 reason/摘要中标注 **`BEFORE_EM_POOL_WINDOW (2026-07-27)`**。
- **涨跌家数在全部日期都是缺口**：07-20~08-13 全区间 riseCount/fallCount/flatCount/suspendedCount 均无法由免费 akshare 历史源补齐（legu 仅当日）。保持 None + 标注 `NO_HISTORICAL_SPOT`。
- **ST 拆分在窗口外的诚实处理**：涨停/跌停池本身在 07-24 及更早不可得，ST/非ST 拆分同样不可得，一并置 None；不要用"当日或无历史"推断历史 ST 数量。
- **dtgc EMPTY 的歧义**：仅当 date >= 07-27 时，EMPTY 才解释为"当日零跌停"；date < 07-27 一律解释为"窗口外不可得"。采集器需显式按日期分支，避免把窗口外误记成零。
- 若日后需要 07-24 及更早的涨跌停，只能转人工/商业源/留存历史快照；免费 akshare 本版本无解。

## 5. 推荐的采集器改动方案（sentiment.py 历史分支数据源顺序）

### 建议顺序：legu → 东财池 → PARTIAL 降级

1. **legu（当日兜底，非历史）**：因 `stock_market_activity_legu()` 仅当日，**历史分支直接跳过 legu**，绝不把它当历史源。仅 `trade_date == today` 实时分支可作补充项——但**注意 legu 只有上涨/涨停/真实涨停/活跃度，没有涨跌家数与炸板**，只能补充实时活跃度，不能取代 spot 涨跌家数。
2. **东财池（历史分支唯一有效源）**：
   - 顺序：`stock_zt_pool_em`（涨停+连板+炸板次数）→ `stock_zt_pool_dtgc_em`（跌停）→ `stock_zt_pool_zbgc_em`（炸板家数）。
   - 若 `date >= 20260727`：正常抓取，名称前缀拆 ST/非ST；`连板数.max()` 得最高连板高度；封板率 = 涨停池数/(涨停池数+zbgc 数)。
   - 若 `date < 20260727`：跳过东财池，直接返回：
       {status: PARTIAL, reason: "BEFORE_EM_POOL_WINDOW (2026-07-27)",
        riseCount/fallCount/flatCount/suspendedCount: None,
        nonStLimitUp/stLimitUp/nonStLimitDown/stLimitDown/brokenLimit: None}
   - **跌停 dtgc 需按日期判定 EMPTY**：>= 窗口 → EMPTY 记为 0（真零）；< 窗口 → None。
3. **PARTIAL 降级语义**：
   - `reason` 区分两类：
     - `HISTORICAL_LIMIT_POOL_ONLY`（date >= 07-27，涨停/跌停/炸板/连板/封板给全，涨跌家数 None）—— 沿用现有语义。
     - `BEFORE_EM_POOL_WINDOW` 或 `HISTORICAL_LIMIT_POOL_WINDOW_BEFORE_20260727`（date < 07-27，所有字段 None）—— 新增，替代现有 `HISTORICAL_LIMIT_POOL_UNAVAILABLE` 的笼统语义，明确不是"接口挂了"而是"历史窗口未覆盖"。
   - 单项失败（如 dtgc 异常）只对单项记 error，不吞已取得的涨停计数（沿用现有"宁缺勿错"）；**绝不用 0 伪装缺失**（除 >= 窗口的 dtgc EMPTY 判定为真零外）。
   - 涨跌家数永远不进历史分支的来源列表：避免误用 legu/spot 当日值回填历史。

### 结论：legu 不作为历史源引入

仅作为实时分支可选增强项，且需明确其字段缺涨跌家数与炸板，不能替代 spot。
