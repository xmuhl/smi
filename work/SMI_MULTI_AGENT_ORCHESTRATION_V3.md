- 日期：2026-08-16

- 复核链：主控自评 v2 → GLM-5.3 复核（work/SMI_Workflow_GLM53_Review.md，4 条实质修正 + 4 块"水泥"）→ 本终版
- 技能落地：multi-agent-dev-workflow SKILL.md 新增「编排效率与墙钟控制」章节

## 一、问题诊断（本会话实测证据）

| # | 根因 | 证据 | 占比 |
|---|---|---|---|
| 1 | workflow 600s 上限 × 5 次超时（任务书含自验证/网络探测；大文件多点编辑本身也超限） | 每次 10 分钟空转，共约 50 分钟；超时时文件均已写盘，验证需主控重做 | 最大 |
| 2 | 长等待置于 workflow/前台，挤掉轮询时机 | ChatGPT 回复早已完成而主控不知（用户指正） | 大 |
| 3 | 全量验证跑在关键路径（未选择性/未后台化） | pytest 全量+基线反复串行 | 中 |
| 4 | 步骤导向任务书迫使主控先探索再派发 | 回合数翻倍 | 中 |
| 5 | 无超时恢复协议：超时后盲目整单重跑 | 再赔 10 分钟 | 大（GLM 指出的最大单项损失源） |
| 6 | pwsh 后台 job 跨回合可能死亡、验证与编辑并发互污 | 组合 pytest 偶发挂起 | 中 |
| 7 | 双分支维护+cherry-pick、主控整读大文件核对产物 | 次要 | 小 |

主控模型（v4-pro）推理本身不是瓶颈；瓶颈在编排机制。

## 二、终版规程（14 条，已入技能）

1. **任务书白名单制**：agent 仅允许 read/edit/py_compile/git status；禁测试套件/基线/网络/pip/循环探测；≤4 项精准改动、按文件边界分组；任务书=目标+验收样例，不写探索步骤。
2. **预算分配**：单 agent 设计墙钟 ≤180s（含 60~90s 冷启动），workflow 总墙钟 ≤450s（75% 上限），超出拆批；并行度 = min(不相交文件组数, 3)；限制单 agent 工作量而非并行数量。
3. **超时恢复**：workflow 末动作落盘 done 清单；报错后读清单+diff --stat 核对，只补缺失项，禁止整单重跑。
4. **主控直做判据**：持有唯一字符串锚点且 ≤3 处局部 edit → 直做；探索型/>100 行新代码/跨文件同模式重复 → flash agent；写任务书成本 ≥ 直做成本 → 直做。
5. **两级门禁**：L0（py_compile/import/diff --stat，秒级、串行、过 gate 必经）；L1（受影响文件选择性 pytest/基线，后台副本隔离）。
6. **后台验证**：脱离进程 + 日志 DONE 标记 + 超时 kill；在 worktree/副本上跑；主控轮询日志文件，不依赖会话内 job 对象。
7. **Gate 收割**：提交前/送审前/派发依赖型下游前/任务切换前强制收割；周期末清单清零。
8. **长等待纪律**：等待绝不入 workflow；外部评审探测 90s→180s→300s→每 300s 与填隙任务交错；完成判定=matched+generating=false+指纹两次一致（间隔 30~60s）→立即取全文；卡死检测（指纹两周期不变且 generating=true）→重发/人工。
9. **回合纪律**：独立短调用同回合并行；workflow 独占回合；发射台回合集中发可并行事项；同文件多 edit 用唯一字符串锚点。
10. **上下文卫生**：diff --stat/清单/头尾核对，不整读大文件。
11. **Git 纪律**：单分支顺序 commit；送审钉输入哈希、报告用新哈希、评审期间禁 rebase/amend；评审只收分支名时用 fast-forward-only 指针分支。
12. **模型方案**：主控编排 + 轻量模型子 agent（用户指定时直接采用）；执行前确认注册名（本环境 opencode-go/deepseek-v4-flash 已实测可用）。
13. **验收分离**：修复/验收不同 agent、文件分区不相交、迭代上限 5 轮（原技能铁律保留）。
14. **数据铁律**：不伪造数据、fail-closed、诚实标注（SMI 项目专属，与原技能铁律并列）。

## 三、GLM-5.3 复核裁决摘要（4 修正 + 4 块水泥）

- 修正 1（原条 1）："≤3 分钟"对 agent 无强制力 → 改为内容约束 + 命令白名单；
- 修正 2（原条 2）："并行不受限"措辞自相矛盾 → 补文件不相交 + 失败核对前提；
- 修正 4（原条 4）：后台化需两级门禁（L0 串行）+ 脱离进程 + 副本隔离 + gate 收割；
- 修正 7（原条 7）：批量并行仅限独立调用；workflow 独占回合；edit 用字符串锚点；
- 水泥 1：超时恢复协议（done 清单，禁止整单重跑）；
- 水泥 2：长等待移出 workflow（历史 600s 阻塞实例）；
- 水泥 3：全量验证改选择性+后台；
- 水泥 4：后台进程存活性（脱离进程+日志，防静默丢失）。

## 四、附：本会话已验证的其它关键事实

- opencode-go/deepseek-v4-flash 为 workflow agent() 可用注册名（provider "opencode" 无效，返回 null）。
- workflow 返回 schema 子集限制：additionalProperties 必须是 boolean，不支持 free-form map 值类型——用数组对象替代。
- flash agent 在无验证负担时编辑速度可接受；超时 5 次均为任务书含验证/网络所致。
- 组合 pytest 挂起曾因"未打补丁的接口触发真实网络请求"——测试隔离要覆盖所有分支路径。
